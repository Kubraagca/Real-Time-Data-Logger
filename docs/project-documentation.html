Realtime Data Logger

Bu proje nasil calisir?

Bu depoda iki ayri cihaz ve iki ayri servis mantigi vardir. Birinci hat Tzone sicaklik sensorlerinin TCP ile veri gonderdigi servistir. Ikinci hat G1 gateway cihazlarinin HTTP veya MQTT ile veri gonderdigi servistir. Bunlar ayni cihazin iki modu degil, birbirinden ayri urun ve ayri haberlesme yapilaridir.

1. Projenin amaci

Amac, Tzone servisini ve G1 servisini birbirine karistirmadan belgelemek; her birinin veri alma yontemini, kullandigi protokolu, endpointlerini ve istemcilere nasil veri sagladigini ayri ayri gostermektir.

Bu belgeyi okurken su mantikla ilerlemek gerekir: once veri cihazda olusur, sonra backend'e gelir, backend bunu isler ve en sonda web veya mobil ekrana yollar. Yani asil soru "hangi protokol kullanildi?" degil, "veri hangi noktadan cikip hangi noktaya gidiyor?" sorusudur.

2. Temel bilesenler

Tzone Servisi

Tzone sensorlerinden gelen TCP paketlerini almak, parse etmek ve Tzone API cikisi uretmek icin kullanilir.

G1 Servisi

Gateway ve beacon verilerini HTTP veya MQTT uzerinden alip G1 API cikisi ureten ayri servis hattidir.

Tzone TCP Dinleyici

Sadece Tzone cihazlarindan gelen TCP baglantilarini dinler. G1 bu hatta dahil degildir.

G1 HTTP / MQTT Girisi

Sadece G1 gateway tarafindan gelen JSON-LONG veya MQTT payloadlarini alir. Tzone bu hatta dahil degildir.

Ayrik Parserlar

Tzone parser'i TCP paket cozer, G1 parser'i JSON payload cozer. Kurallar ortak degildir.

Istemciler

Web panel ve Flutter uygulamasi her iki servisin cikisini backend API ve Socket.IO uzerinden ayri tablarda gosterir.

3. Senaryo anlatimi

Senaryo 1: Tzone verisi nasil ilerler?

Baslangic: Tzone sicaklik sensoru kendi icinde olcum yapar. Sicaklik, nem, pil veya benzeri bilgiler cihazin icinde olusur.
Ilk durak: Bu veri Tzone cihazindan cikar ve internet uzerinden backend'deki Tzone TCP servisinin portuna gelir.
Backend'de ne olur? Backend paketi oldugu gibi alir, ham veriyi kaybederim diye once loglar, sonra Tzone parser'i ile anlamli alanlari ayiklamaya calisir.
Sonra nereye gider? Ayrilan veri Tzone kaydi olarak saklanir. Ardindan ayni veri tzone:reading event'i ile canli yayina verilir.
Kullanici nerede gorur? Web panel veya mobil uygulama bu Tzone kaydini ya API ile ceker ya da Socket.IO ile canli olarak alir.

Senaryo 2: G1 gateway verisi nasil ilerler?

Baslangic: G1 gateway etraftaki beacon veya kendi durum bilgilerini toplar. Ornegin RSSI, rawData, gatewayFree veya gatewayLoad gibi alanlar burada olusur.
Ilk durak: Bu veri gateway'den cikar ve HTTP POST veya bazen MQTT ile backend'deki G1 servisine gelir.
Backend'de ne olur? Backend G1 payload'ini alir, JSON olarak parse eder ve bunun gateway kaydi mi beacon kaydi mi oldugunu anlamaya calisir.
Sonra nereye gider? Veri G1 kaydi olarak saklanir. Ardindan ayni veri g1:reading event'i ile canli yayina verilir.
Kullanici nerede gorur? Web panel veya mobil uygulama bu G1 kaydini G1 endpoint'lerinden veya G1 Socket event'inden alir.

4. Protokol ozeti

Tzone ve G1 ayni protokolun varyanti degildir. Asagidaki ozet, bu iki servisin birbirinden ayri calistigini netlestirir.

Kisa ozetle: Tzone verisi "sensor -> Tzone TCP servisi -> Tzone kaydi -> Tzone ekrani" yolundan gider. G1 verisi ise "gateway -> G1 HTTP/MQTT servisi -> G1 kaydi -> G1 ekrani" yolundan gider.

Tzone Hatti

  • Transport: TCP
  • Varsayilan port: 18801
  • Paket tipi: Binary veya ASCII
  • Source: tzone
  • Canli event: tzone:reading

G1 Gateway Hatti

  • Birincil transport: HTTP POST
  • Opsiyonel transport: MQTT
  • Veri formati: JSON-LONG
  • Source: g1
  • Canli event: g1:reading

Istemci Hatti

  • Ilk yukleme: REST API
  • Canli akis: Socket.IO
  • Web: HTTP GET + Socket.IO
  • Mobil: HTTP GET + Socket.IO
  • Dogrudan cihaza baglanti: Yok, istemci sadece ilgili servisin backend cikisina baglanir
Hat Kim veri gonderiyor? Protokol Giris noktasi Backend cikisi
Tzone Tzone TT18-4G-M sicaklik sensoru TCP binary / ASCII Ayri Tzone TCP listener servisi Tzone API ve tzone:reading
G1 HTTP Gateway cihazinin kendisi HTTP POST JSON-LONG Ayri G1 HTTP ingest servisi: /gw/:gatewayMac/status veya /api/g1/http G1 API ve g1:reading
G1 MQTT MQTT broker uzerinden gateway verisi MQTT JSON Ayri G1 MQTT subscribe servisi: /gw/+/status topic'i G1 API ve g1:reading
Web / Mobil Web panel ve Flutter uygulamasi REST + Socket.IO HTTP API ve Socket.IO server Ekranda gecmis kayit + canli akis

5. Tzone icin daha acik anlatim

Tzone tarafini bir kargo akisi gibi dusunebiliriz. Paket cihazdan cikar, Tzone'a ayrilmis servis kapisina gelir, backend icerde paketi acip icindeki bilgileri okur, sonra o bilgiyi Tzone verisi olarak saklar ve kullanici ekranina yollar.

  • Tzone cihazi backend'in TCP portuna baglanir. Varsayilan port 18801'dir.
  • Backend paketi alir ve rawHex ile asciiPreview bilgisiyle birlikte loglar.
  • Parser veri tipini binary, ascii veya unknown olarak tahmin eder.
  • Binary paket uygun ise imei, temperature, humidity, battery, light, rtcTime ve packetIndex ayrilir.
  • packetIndex varsa backend cihaza ACK yollar: @ACK,<packetIndex>#
  • Parse edilemeyen veri de kaybolmaz; ham veri olarak yine saklanir.

Tzone'dan cikan alanlar

  • imei
  • temperature
  • humidity
  • light
  • battery
  • receivedAt
  • rawHex
  • packetIndex

Ornek Tzone event payload

{
  "imei": "862938475612345",
  "source": "tzone",
  "temperature": 25.4,
  "humidity": 60.0,
  "light": 1,
  "battery": 3.71,
  "receivedAt": "2026-06-26T09:15:30.000Z",
  "rawHex": "404441544123",
  "packetIndex": 12
}

6. G1 icin daha acik anlatim

G1 tarafini da ayri bir kargo akisi gibi dusunmek gerekir. Burada veri Tzone gibi TCP paket halinde degil, daha cok JSON kaydi olarak gelir. Gateway ne gorduyse veya ne olctuyse onu G1 servisine yollar; backend de bunu G1 verisi olarak saklar ve G1 ekranina yollar.

  • G1 tarafinda veri birincil olarak HTTP POST ile gelir.
  • Gateway ayarinda tipik kullanim: Service Access = HTTP, Data Format = JSON-LONG
  • Normal endpoint: /gw/:gatewayMac/status
  • Alternatif test endpoint'i: /api/g1/http
  • HTTP disinda ayni veri yapisi MQTT ile de alinabilir.
  • MQTT aciksa backend broker'a baglanir ve varsayilan olarak /gw/+/status topic'ine subscribe olur.

G1 parser hangi alanlari okur?

  • timestamp
  • type
  • mac
  • bleNo
  • bleName
  • rssi
  • rawData
  • gatewayFree
  • gatewayLoad
  • opsiyonel olarak temperature, humidity, battery

G1 veri yorumu

  • type = "Gateway" ise bu satir gateway durum bilgisidir.
  • Diger tipler beacon veya BLE tarama kaydi gibi ele alinir.
  • mac alani bu tarafta cihaz kimligi olarak kullanilir.
  • rawData beacon ham datasidir ve arayuzde gosterilebilir.

Ornek G1 payload

[
  {
    "timestamp": "2026-01-21T05:51:02.183Z",
    "type": "Gateway",
    "mac": "AC233FC1CE60",
    "gatewayFree": 96,
    "gatewayLoad": 0.12
  },
  {
    "timestamp": "2026-01-21T05:51:05.407Z",
    "type": "Unknown",
    "mac": "1D0C3C98FA38",
    "bleNo": 0,
    "bleName": "",
    "rssi": -35,
    "rawData": "1EFF060001092002651416D5B7EE1C2F1FB30C54985490054A17AE79D5F0BF"

8. API ve Socket cikislari

REST endpointleri

  • GET /health - Sistem sagligi, database, G1 MQTT ve HTTP durum bilgisini doner.
  • GET /api/tzone/readings/latest - Son Tzone kayitlarini doner.
  • GET /api/tzone/devices - Tzone cihaz listesi ve online durumunu doner.
  • GET /api/tzone/devices/:imei/readings?limit=100 - Tek Tzone cihaz gecmisi.
  • POST /api/g1/http - Alternatif G1 HTTP ingest endpoint'i.
  • POST /gw/:gatewayMac/status - Gateway'in normal veri gonderdigi endpoint.
  • GET /api/g1/readings/latest - Son gateway ve beacon kayitlarini doner.
  • GET /api/g1/devices - G1 cihaz listesi ve ozetlerini doner.
  • GET /api/g1/devices/:imei/readings?limit=100 - Tek G1 cihaz gecmisi.

Socket.IO eventleri

  • tzone:reading - Tzone sensorunden gelen yeni tekil kayit
  • g1:reading - Gateway veya beacon tarafindan gelen yeni tekil kayit

9. Web ve mobil istemci mantigi

  • Web panel ve Flutter uygulamasi Tzone cihazina veya gateway'e direkt baglanmaz.
  • Tzone verisi Tzone endpoint ve event'lerinden, G1 verisi G1 endpoint ve event'lerinden alinir.
  • Ilk ekran yuklenisinde son kayitlar HTTP GET ile cekilir.
  • Yeni kayitlar ilgili servis event'i ile Socket.IO uzerinden anlik ekrana duser.
  • Bu nedenle Tzone tarafi calisirken G1 tarafi kapali olabilir veya tersi de olabilir.

Yani kullanicinin gordugu ekran en sondaki duraktir. Veri once cihazda dogar, sonra backend'e gelir, backend onu ilgili servise koyar, en son web veya mobil bunu gorur.
